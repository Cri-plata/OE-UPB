# Reglas de Negocio (OE UPB)

> **Estado:** política aprobada el 2026-09-23 e implementada para RBAC, permisos, programas y publicación de gráficas. La matriz de trazabilidad conserva el estado por requisito.

Las reglas de negocio dictan las validaciones obligatorias del backend. La interfaz puede ocultar acciones por conveniencia, pero nunca sustituye estos controles.

1. **RN-01 Unicidad del Egresado:** `numero_documento` (cédula) es el identificador único de un egresado identificado. El sistema no debe crear dos egresados con el mismo documento. Si una carga contiene un documento ya persistido, debe actualizar el registro conforme a la política de precedencia aprobada, no duplicarlo. Los duplicados dentro del mismo archivo se resuelven conforme a ADR-006.
2. **RN-02 Integridad de Momentos:** El sistema solo aceptará encuestas catalogadas bajo `Momento 0` (grado), `Momento 1` (al año) y `Momento 5` (a los cinco años). Cualquier otro valor será rechazado.
3. **RN-03 Rol de Consulta:** Rector, profesor y personal administrativo usan un único rol técnico, `Usuario_Consulta`. Este rol es siempre de solo lectura y no puede cargar archivos, eliminar registros, publicar gráficas ni administrar cuentas.
4. **RN-04 Anonimización (Privacidad):** Antes de enviar texto a una API de inteligencia artificial externa, el backend debe remover documentos, nombres propios y correos electrónicos. La misma prohibición de exponer datos personales o respuestas individuales aplica a las gráficas compartidas entre sedes.
5. **RN-05 Formato de Carga:** El único formato permitido para la carga masiva es `.xlsx`. El frontend debe rechazar otros formatos antes del envío y el backend debe volver a validar la extensión y el contenido.
6. **RN-06 Aislamiento de Datos Fuente por Sede:** Los egresados, mediciones, respuestas individuales, archivos e historiales de carga solo pueden ser consultados o modificados dentro de la sede autorizada por el JWT. Ningún permiso de visualización compartida concede acceso a estos datos fuente de otra sede.
7. **RN-07 Separación de Administración de Cuentas:** `Admin_CTIC` crea, modifica, bloquea o elimina cuentas `Coordinador_Sede`. Cada `Coordinador_Sede` administra únicamente cuentas `Usuario_Consulta` de su propia sede y no puede crear coordinadores, cuentas CTIC ni usuarios de otra sede.
8. **RN-08 Permisos del Usuario de Consulta:** Al crear un `Usuario_Consulta`, el coordinador debe asignar manualmente sede, programas autorizados y permisos de visualización. La audiencia se calcula automáticamente con esos atributos; no se seleccionan destinatarios manualmente al publicar cada gráfica.
9. **RN-09 Publicación de Gráficas Agregadas:** Cada gráfica publicable dispone de una acción `Publicar`. Solo el coordinador propietario de los datos puede activarla o retirarla. La publicación comparte exclusivamente la gráfica y sus métricas agregadas, nunca filas, documentos, nombres, correos, respuestas individuales ni el archivo fuente.
10. **RN-10 Alcance de Visualización Compartida:** Un coordinador autenticado puede ver todas las gráficas publicadas por otras sedes sin requerir asignación individual de programas. Para todo `Usuario_Consulta`, la visibilidad se limita estrictamente a los permisos y programas seleccionados manualmente; ninguna etiqueta de perfil concede acceso implícito.
11. **RN-11 Autorización Derivada:** La visibilidad de una gráfica publicada se determina en backend a partir de su estado de publicación y sede propietaria. Para un coordinador se aplica el acceso general definido en RN-10; para un `Usuario_Consulta`, además se validan alcance, programas asociados y permisos asignados. El cliente no puede ampliar ese alcance enviando una sede, programa o rol diferente.
12. **RN-12 Carga Auditable y Reemplazo:** Cada archivo constituye una carga con identidad propia. Una recarga para la misma sede, momento y año de grado reemplaza la versión vigente en una única transacción; un fallo conserva la versión anterior completa.
13. **RN-13 Precedencia y Edición Manual:** Una corrección manual queda protegida frente a cargas posteriores. El coordinador puede registrar encuestas manuales y corregir egresados visibles para su sede, con auditoría de actor, fecha, procedencia y campos. La custodia institucional resuelve conflictos sobre la identidad global entre sedes.
14. **RN-14 Publicación Versionada y Privacidad:** Una gráfica publicada es una instantánea versionada e inmutable de las métricas agregadas aprobadas. Su definición permite renderizarla y auditarla, pero no recalcularla automáticamente con datos posteriores. Cualquier actualización crea una versión nueva y requiere una nueva aprobación manual de privacidad. No existe todavía un umbral numérico automático aprobado.
15. **RN-15 Mediciones Anónimas:** Las mediciones sin documento solo pueden participar en agregados aprobados. No deben aparecer en directorios, perfiles ni comparaciones longitudinales M0/M1/M5.
16. **RN-16 Taxonomía Laboral:** El estado laboral principal pertenece a `empleado`, `independiente`, `estudiante` o `sin_empleo`. La formalidad es un atributo separado cuando resulte aplicable.
17. **RN-17 Año de Grado:** El año recibido durante la carga representa el año de grado o cohorte, no el año de aplicación de la encuesta.
18. **RN-18 Activación por Contraseña Temporal:** Al crear una cuenta, el formulario solicita la cédula del usuario y el backend la usa como contraseña temporal inicial. Solo se almacena su hash; no se conserva una copia adicional de la cédula con fines de autenticación. El primer login permite exclusivamente establecer una contraseña personal; cualquier otra operación se rechaza hasta completar el cambio. El endurecimiento posterior de este mecanismo está diferido hasta completar RBAC y el flujo funcional.
19. **RN-19 Correo Institucional:** Las cuentas del sistema deben usar un correo terminado en `@upb.edu.co`. El frontend puede anticipar el error, pero el backend vuelve a validar el dominio antes de crear la cuenta.
20. **RN-20 Atomicidad de Archivo:** La carga opera bajo todo-o-nada. Si cualquier fila incumple una validación obligatoria, se revierte el archivo completo y se informa el detalle. Los campos opcionales ausentes y las mediciones anónimas permitidas por RN-15 no constituyen por sí mismos un error.
21. **RN-21 Ciclo de Vida de Cuenta:** La eliminación ordinaria desactiva la cuenta, impide nuevas sesiones y conserva relaciones y auditoría. El borrado físico solo existe como proceso excepcional, restringido y auditado, y se ejecuta cuando la integridad referencial lo permita.
22. **RN-22 Vigencia Inmediata de Autorización:** Un bloqueo o reducción de permisos tiene efecto inmediato. Cada operación protegida valida en backend el estado y la versión de autorización vigentes; un JWT emitido previamente no conserva permisos revocados.
23. **RN-23 Eliminación Auditada de Carga:** Eliminar una carga borra físicamente, dentro de una única transacción, la carga y sus mediciones. Antes del borrado se conserva en una entidad separada un evento inmutable con identificador de carga, actor, sede, momento, cohorte, fecha, versión, cantidad de registros y motivo.
24. **RN-24 Consulta Exclusiva de Publicaciones:** `Usuario_Consulta` solo puede ver instantáneas publicadas compatibles con sus permisos y programas. No accede a gráficas privadas ni a datos fuente, incluso dentro de su propia sede.
25. **RN-25 Mediciones Repetidas:** Pueden existir múltiples mediciones válidas para el mismo documento, sede, momento y cohorte. Cada indicador debe declarar en su diccionario si selecciona, ordena o agrega intentos; ningún cálculo puede contar múltiples intentos sin una regla explícita.
26. **RN-26 Suficiencia por Indicador:** No existe un umbral global de datos suficientes. Cada indicador define población, mínimo de observaciones o pares, tratamiento del conjunto insuficiente y mensaje resultante. Esta regla no sustituye la aprobación manual de privacidad de RN-14.
27. **RN-27 Sede en Interfaces Analíticas:** El dashboard privado deriva siempre la sede del JWT y no ofrece un selector para cambiarla. Las publicaciones agregadas de otras sedes se consultan en una vista separada.
28. **RN-28 Catálogo Inicial de Permisos:** Los permisos asignables a `Usuario_Consulta` son `ver_reporte_general`, `ver_tendencias`, `ver_explorador` y `ver_publicaciones`. La exportación no forma parte de este catálogo inicial. Cualquier permiso nuevo requiere actualizar reglas, contratos, interfaz y pruebas de autorización.
29. **RN-29 Fuente de Programas Asignables:** La lista de programas se obtiene de los valores distintos observados en cargas visibles para la sede del coordinador. El backend genera la lista y valida cada asignación; el cliente no puede introducir un programa arbitrario ni uno observado exclusivamente en otra sede.
30. **RN-30 Etiquetas de Perfil:** Rector, profesor y administrativo son etiquetas informativas de `Usuario_Consulta`. No son roles técnicos ni plantillas de autorización. Todos los permisos y programas se configuran manualmente y se aplican de la misma manera sin importar la etiqueta.
31. **RN-31 Variables Analíticas Permitidas:** El Explorador solo puede consultar y publicar variables incluidas en un catálogo analítico autorizado por el backend. Se excluyen documentos, nombres, apellidos, correos, teléfonos, fechas personales, identificadores de respuesta/encuesta y códigos administrativos o institucionales. El frontend no puede ampliar este catálogo.
